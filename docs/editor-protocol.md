# Протокол редактора Volna (SysEx по USB-MIDI)

Версия **5** (2026-11-20).
- **v1**: сведения об устройстве, имена патчей, чтение и запись патчей. Этим пользуется библиотекарь.
- **v2**: параметры панели (описание, раскладка страниц, чтение и правка) и уведомления о правках на панели. Этим пользуется редактор.
- **v3**: пользовательские таблицы волн: сведения о слотах, загрузка таблицы, имя, очистка. Этим пользуется вкладка Wavetables.
- **v4**: самостоятельный рисунок каждого патча, отдельная библиотека заготовок и SAVE текущего патча. Старые ссылки нормализуются при чтении; подробности — [patterns.md](patterns.md).
- **v5**: номер исходной заготовки сохраняется в патче и показывается в LOAD. Обмен рисунком может включать этот номер.

Команды прежних версий сохраняют свой формат. Реализация в прошивке: `firmware/src/editor.h` (кадры, разбор, ответы) и `firmware/src/volna.c` (`ed_*`). Эти команды использует [веб-редактор Volna](https://soundplayground.twc1.net/fm1-firmwares/volna/#editor).

Путь обновления (M-UPGRADE, `F0 00 32 45 …`, `F0 22 24 35 7F F7`) этим не затронут: кадры редактора начинаются с другого байта, и платформа отдаёт их приложению, не трогая свои (`ota.c`, `OTA_APP_FRAME`).

## Кадр

```
F0 7D 56 4C  pack7( cmd | seq | payload… | sum )  F7
```

- `7D` — ID «для некоммерческого использования», `56 4C` — «VL».
- `pack7` — тот же сплошной поток бит LSB-first, что у протокола обновления: 8 бит данных уходят в 7-битные байты подряд, без групп по 7.
- `cmd` — команда; ответ несёт `cmd | 0x80`.
- `seq` — номер запроса, любой; ответ повторяет его.
- `sum = ~(cmd + seq + сумма payload) & 0xFF`.
- Кадр от компьютера — не больше 640 байт между `F0` и `F7` (буфер платформы), то есть до 556 байт `cmd … sum`. Кадр с ошибкой в сумме или длине устройство молча пропускает.

Ответ всегда начинается со **статуса**: `cmd|0x80, seq, status, данные…, sum`.

| status | значение |
| --- | --- |
| 0 | готово |
| 1 | неверный запрос (длина, номер) |
| 2 | патч не подходит (версия записи, размер, значения вне диапазонов); у таблицы — не сошлась CRC |
| 3 | занято: ждёт предыдущая запись (своя, таблицы или SAVE с панели) |
| 4 | запись во флеш не удалась |
| 5 | неизвестная команда |

Числа — little-endian.

## Команды

### `01` INFO

Запрос: без данных. Ответ (статус 0):

| байты | что |
| --- | --- |
| 1 | версия протокола (4) |
| 1 | число патчей (100) |
| 2 | `sizeof(patch_t)` в этой сборке (на 2026-11-19: 272; до v4 — 266) |
| 2 | предел записи патча, `P2MAX` (494) |
| 1 | номер патча, из которого звук (0..99) |
| 1 | 1, если звук изменён и не сохранён |
| 8 | имя прошивки, ASCII с нулями (`VOLNA`) |
| 8 | версия (`APP_VER`), ASCII с нулями |
| 1 | v2: число параметров (`NPARAM`, id 1..NPARAM−1; 0 — пустая ручка) |
| 1 | v2: число разделов панели (`NSEC`) |

### `02` NAMES

Запрос: `first`, `count` (`count` 1..25, `first + count` ≤ 100). Ответ: `first`, `count`, затем `count` имён по 12 байт (пробелы в конце). Патч, который ни разу не сохраняли, называется по заводскому звуку этого номера, иначе `INIT`.

### `10` PATCH GET

Запрос: `slot` — 0..99 или `7F` (звук, который сейчас играет, с правками). Ответ: `slot`, затем **запись**.

### `11` PATCH PUT

Запрос: `slot`, затем запись.
- `slot` 0..99 — запись во флеш. Она ждёт тишины, как SAVE с панели: ответ придёт после записи, и это может быть не сразу. Если этот номер сейчас загружен и не изменён, звук перезагружается из него.
- `slot` `7F` — в звук, который сейчас играет, без флеша. Звук считается изменённым относительно своего номера, как после правки ручками.

Ответ: `slot`.

## Параметры (v2)

Параметры — те же, что крутят ручки панели (`PARAM`, `pget`, `pset` в `ui.h`). Правка идёт как с ручки: значение ограничивается диапазоном, затем `pset` и звук. Побочные действия те же: новый тип эффекта берёт свои начальные значения, SYNC переводит RATE в доли такта и т. п.

У многих параметров есть **экземпляр** (`inst`) — то, что на панели выбирает SELECT:

| вид | что | сколько |
| --- | --- | --- |
| 0 | нет (параметр один) | 1 |
| 1 | осциллятор | 3 |
| 2 | фильтр | 2 |
| 3 | огибающая (AMP, FLT, 3, 4) | 4 |
| 4 | LFO | 3 |
| 5 | слот матрицы | 16 |
| 6 | модификатор | 4 |
| 7 | слот эффекта (EQ — без экземпляра) | 2 |
| 8 | шаг паттерна арпа (того, что играет) | 16 |

### `20` PDESC

Запрос: `first`, `count` (1..16). Ответ: `first`, `count`, затем по 16 байт на параметр: имя (8, ASCII с нулями), `lo` (int16), `hi` (int16, наибольший вообще), шаг ручки, формат (`F_*`), вид экземпляра, 1 — если это настройка, а не патч (MIDI, CURVE, TUNE, MORPH, CTL W..Z…).

### `21` PVAL и `22` PSET

PVAL — запрос: `inst`, `id`. PSET — запрос: `inst`, `id`, значение (int16).

Ответ у обоих: `inst`, `id`, значение (int16), `hi` сейчас (int16; у синхронизированного RATE, например, это число долей такта), число названий вариантов сейчас (0 — число), затем текст значения, как его показывает ячейка (ASCII до конца кадра).

### `23` PCHOICES

Запрос: `inst`, `id`, `first`, `count` (1..16). Ответ: те же четыре байта, затем названия, каждое с нулём в конце. Названия могут зависеть от экземпляра: цели матрицы — от группы слота, RATE — от SYNC.

### `24` LAYOUT

Запрос: раздел (0..NSEC−1), экземпляр (у FX 2 — EQ). Ответ: раздел, экземпляр, вид экземпляра раздела, число рядов, имя раздела (8), затем ряды по 4 id (0 — пусто), как их показывает панель для этого экземпляра. У FX ряды зависят от типа эффекта; у MOD ряды A и B — LFO, C — слот матрицы, D — модификатор.

### `25` WATCH

Запрос: 1 — следить, 0 — нет. Пока страница следит, устройство шлёт **CHANGED** (`E0`, seq 0, статус 0): номер патча, 1 если звук изменён, 1 если загружен другой патч. Оно приходит не чаще раза в 100 мс, когда звук или настройки поменялись не по команде страницы (ручкой, PRESETS, program change). Правки самой страницы CHANGED не вызывают. WATCH гаснет через 10 с без повтора: закрытая страница не забивает USB.

### Запись патча

Та же, что во флеше (формат 2, `prec2_t` в `volna.c`), без хвоста после `size`:

| байты | что |
| --- | --- |
| 1 | версия формата (2) |
| 1 | 0 |
| 2 | `size`: сколько байт `patch_t` дальше (8..494) |
| 12 | имя (символы `" A-Z0-9-."`; при записи остальные становятся пробелами, строчные — заглавными) |
| `size` | `patch_t` как в памяти |

`patch_t` только растёт с конца. Короче, чем в сборке: недостающее берётся из `PATCH_DEFAULT`. Длиннее: лишнее отбрасывается. После этого патч проверяется (`patch_ok`), и неподходящий не принимается (статус 2).

## Таблицы волн (v3)

Пользовательских слотов **4**, номера таблиц у них **59–62** (на ручке TABLE — последние четыре позиции, после ANALOG и локальных таблиц). Номера постоянные: патч, который ссылается на 59, играет первый слот в любой сборке. Пустой или испорченный слот звучит как BASIC, а на экране называется `USER 1 EMPTY`..`USER 4 EMPTY`: патч на нём не молчит, и видно, что таблицы нет.

Таблица — та же, что встроенные (`engine/wt_osc.h`): `WT_WORDS` = 24 960 значений int16 (little-endian), 49 920 байт: 64 волны по 128 точек, затем их mip-maps. mip-maps считает сайт, устройство только хранит. Во флеше FM-1 слот — 14 секторов с `0xA4000` (`store.h`): заголовок (магия `VWT1`, длина, CRC, имя) в первом, таблица со второго. Звук читает её прямо из флеша (окно XIP без шифрования). Таблица переживает установку Volna, как патчи. На SMK-37 слотов нет: команды отвечают «неизвестная команда».

CRC — CRC-32 как у zlib (`zlib.crc32`, полином `EDB88320`) по 49 920 байтам таблицы.

### `30` TABLE INFO

Запрос: без данных. Ответ: число слотов (4), номер первой таблицы (59), размер таблицы в байтах (uint32, 49 920), наибольший кусок TABLE DATA (uint16, 512); затем по 17 байт на слот: 1 — если в нём таблица, CRC (uint32; 0 у пустого), имя (12, пробелы в конце).

### `31` TABLE BEGIN

Запрос: слот (0..3), CRC всей таблицы (uint32), имя (12; как у патчей: `" A-Z0-9-."`, строчные — заглавными, остальное — пробелы). Слот сразу становится пустым (голоса на нём играют BASIC) и стирается, **когда станет тихо**, как запись патча: ответ (слот) приходит после стирания, ~0,7 с. Занято (статус 3), если ждёт другая запись.

### `32` TABLE DATA

Запрос: слот, смещение (uint32), до 512 байт таблицы. Только после BEGIN этого слота и **строго по порядку**: смещение — ровно следующий ожидаемый байт. Иначе — статус 1. Ответ: слот, смещение. Запись идёт сразу, без ожидания тишины (страница по 256 байт, ~1 мс).

### `33` TABLE END

Запрос: слот. Все 49 920 байт должны быть получены. Устройство читает таблицу обратно из флеша и считает CRC: совпала с BEGIN — пишется заголовок, слот заполнен, патчи на нём сразу звучат им (статус 0). Не совпала — статус 2, слот остаётся пустым. Ответ: слот.

### `34` TABLE NAME

Запрос: слот, имя (12). Только у заполненного слота (иначе статус 3). Переписывает заголовок, когда станет тихо (стирание одного сектора, ~50 мс), таблицу не трогает. Ответ: слот.

### `35` TABLE CLEAR

Запрос: слот. Стирает заголовок, когда станет тихо: слот пуст, голоса на нём играют BASIC. Сама таблица остаётся во флеше до следующей загрузки. Ответ: слот.

## Паттерны и SAVE (v4)

Текущий патч всегда содержит свой рисунок. Библиотека — 16 заготовок, номера слотов **0..15**; специальный слот **7F** означает рисунок текущего звука. Чтение любого слота не переключает патч и не влияет на звучание.

### `40` PATTERN INFO

Запрос без данных. Ответ: число заготовок (16), шагов в рисунке (16), версия формата рисунка (1).

### `41` PATTERN GET

Запрос: слот (0..15 или 7F). Ответ: слот, версия формата (1), STEPS (1..16), T.AMT (0..127), затем 16 шагов uint16 little-endian. Всего 36 байт после статуса.

С v5 запрос `7F 01` возвращает те же данные и один байт в конце с номером исходной заготовки (1..16, 0 — номер неизвестен). Обычный запрос из одного байта сохраняет прежний формат ответа.

В шаге: биты 0..2 TYPE, 3 GLIDE, 4..6 ACCENT, 7..9 LENGTH, 10..12 TIMING, 13 TIE. Биты 14..15 должны быть нулевыми. TYPE: NORM, PAUSE, PREV, FIRST, LAST, F+L, CHORD, RAND (0..7). LENGTH 0 — LEG, 1..7 — −3..+3; TIE хранится отдельно (панель показывает его как LENGTH 8). ACCENT 0 — MUTE, 1..7 — −96..+96; TIMING 0 — RAND, 1..7 — −3..+3.

### `42` PATTERN PUT

Запрос: те же 36 байт, что ответ GET. Ответ: слот. Длина, версия, диапазоны и старшие биты шагов проверяются до изменения данных.

С v5 для `7F` принимается 37-й байт с номером исходной заготовки (0..16). При записи в `7F` без этого байта номер сбрасывается. Слоты самой библиотеки принимают прежние 36 байт.

- Слот 7F: копия в текущий патч без записи во флеш; загруженные заготовка и патч после этого независимы.
- Слот 0..15: явная запись заготовки в библиотеку. Если звучат голоса/хвосты или работает арп — BUSY (3), нужно остановить звук и повторить. При принятии запрос фиксирует копию данных; ответ приходит после записи и проверки чтением. FLASH (4) означает ошибку; предыдущая активная библиотека остаётся в RAM и в другом секторе.

Для загрузки заготовки в звук клиент выполняет GET выбранного слота, затем PUT 7F. С v5 в PUT добавляется номер слота плюс один. Для сохранения заготовки — GET 7F, затем PUT выбранного слота без номера источника. Undo замены хранит предыдущий рисунок и возвращает его вместе с номером источника, когда сессия поддерживает v5.

### `43` SAVE

Запрос без данных. Снимает копию текущего патча и имени, останавливает арп и ждёт затухания, как SAVE на панели. Ответ: номер записанного патча (0..99), только после записи; при ошибке — FLASH. При уже ожидающем SAVE — BUSY. При переключении патча во время ожидания записывается исходный снимок в исходный номер. Текущий патч становится сохранённым только если соответствует записанному снимку.

## Файлы на сайте

- **Патч**: `.syx` из одного кадра `PATCH PUT` в `7F`. Его можно отправить любой SysEx-программой: звук сразу загрузится.
- **Банк**: `.syx` из кадров `PATCH PUT` в 0..99 по порядку. Восстанавливается со страницы: она ждёт ответа на каждый кадр (запись ждёт тишины).
- **Рисунок / библиотека заготовок**: JSON `{ "format": "volna-patterns", "version": 1, "patterns": [...] }`, где каждый элемент — `{ "length": 16, "timingAmount": 64, "steps": [16 чисел 0..16383] }`. Файл содержит один рисунок или все 16 заготовок. Все элементы проверяются до начала восстановления; запись библиотеки идёт по слотам, с проверкой ответа каждого. При ошибке клиент сообщает, сколько слотов уже записано. Бэкап 100 патчей содержит их собственные рисунки; отдельный бэкап заготовок сохраняет библиотеку.
